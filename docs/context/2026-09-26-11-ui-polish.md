# 2026-09-26-11 · UI polish + evaluation readiness

## What changed
The user asked for a better UI and help running the first evaluation before continuing M9. This branch is `feat/ui-polish`, stacked on `feat/m9-weather`.

- **The first real visual review.** The browser pane was visible this time, so I took screenshots at 1440×900 in dark and light mode and at 375 px. That surfaced three problems: there was no first-run guidance, map pins and cards weren't linked, and "Something changed?" sat below the fold, away from the plan.
- **`frontend/src/App.tsx`** (render rewritten; logic unchanged):
  - **Header:** a brand mark (📍), the tagline "What can you actually do next, and why?", 🧭/🏪 tabs, the clock and live-weather chip on the right, and a thin **busy bar** at the top during any request.
  - **Welcome state:** a "Try it in 3 steps" card, with **▶ Try the family example** doing it in one click, plus the pitch sentence.
  - **Cards ↔ map:** a number badge (1, 2, 3…) for options and a letter (A, B…) for plan stops, matching the map pins exactly. A map **legend** overlay explains them.
  - **Cards:** category icons, "N min away", and ⚠ reasons in warning colour. A planned card shows "✓ In your plan as stop B" instead of a disabled button.
  - **Layout:** "Your plan" and "Something changed?" are stacked in the right column, so a disruption and its diff sit next to the plan.
  - **Events and changes:** the event buttons have icons, and the change list uses readable labels (🕑 Moved / 🔁 Swapped / ➖ Dropped / ⚠ At risk).
  - **Other:** Enter sends a chat message (Shift+Enter for a newline), a 💰 spend/budget chip, and a mode icon.
- **`frontend/src/styles.css`** was rewritten: softer panels with shadows, a gradient primary button, secondary buttons, token-based light and dark themes, card hover, the welcome-step grid, the legend, label badges, and responsive breakpoints at 1100 and 900 px.
- **`frontend/index.html`:** a better title, a description and an emoji favicon.
- **`scripts/dev.py`** is hardened for evaluation day:
  - It checks for Python ≥ 3.12 and npm with plain messages, and detects busy ports 8000/5173 ("Is the app already running?").
  - It prints first-run setup notes, waits until both servers answer, prints "OK - running", and **opens the browser**; `--no-browser` skips that.
  - Output is ASCII-only, so legacy Windows code pages can't crash it.
- **Docs:** `docs/demo.md` was updated for the new labels and flow (plus the live forecast check and troubleshooting). The README quick start is now `python scripts/dev.py --reset`, with a troubleshooting table.
