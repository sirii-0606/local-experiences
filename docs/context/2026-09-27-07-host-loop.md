# Host loop: accounts, booking requests, demand near you

## What changed
- **Host accounts + My listings.** Publishing while signed in attaches the listing to the account (`listing_users` table) and makes a traveler a `provider`. The host can edit, pause and remove it from any device without the edit token (the token still works for older listings). `GET /me/listings`.
- **Booking requests.** On Explore, cards for listings that have a host account show "Request to book" (time, party size, optional note). The host's Requests tab accepts or declines. Accept makes a real booking with a code, which unlocks a verified-visit review. Travelers see their requests in Profile and can cancel them (an accepted one frees its booking). The backend checks that the listing runs at that time, isn't paused, and has room. Hosts see the display name, party, time and note only.
- **Demand near you.** `/chat` also logs a ~5 km cell (0.05°), intents and "unmet" intents (asked for, none of the recommendations offered). `GET /providers/demand?lat&lon` aggregates the cell and its neighbours over 30 days, with details withheld below 3 searches. Shown per listing in My listings.
- **Host page:** tabs are now List an experience · My listings · Requests (with a pending badge). Signed out, drafting works but publishing asks to sign in. The old "insights for any experience" picker is gone; hosts see their own listings.
- `/catalog` gains `requestable[]`. `/me/export` includes requests and listing ids. `DELETE /me` withdraws pending requests, anonymises the name in hosts' inboxes, and detaches listings.

## Why
The user said the vendor/host side "doesn't feel satisfactory", and chose all three: host accounts + my listings, a booking requests inbox, and demand near you.

## Known gaps
- No notifications: hosts and travelers see changes when they open the page (Refresh button).
- No payment and no messaging beyond the one note.
- "Unmet" only counts intents that none of the top recommendations offered. In a well-covered area like Jaipur it's usually empty.
- Listings published anonymously before this change can't take requests until they're republished while signed in.
