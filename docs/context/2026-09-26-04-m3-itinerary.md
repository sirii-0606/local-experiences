# 2026-09-26-04 · M3: itinerary engine

## What changed
- **`backend/app/engine/itinerary.py`** (new):
  - `gaps(itinerary, state)` finds free windows of at least 30 min. Each gap records where you start (the previous stop) and where you must be when it closes (the next stop, or the state's end point). Relaxed pace adds 20 min of slack after each stop.
  - `fill_gap(itinerary, gap, state, seed)` is just `discover()` on a narrowed state: the origin is the previous stop, the window is the gap, the end point is the next stop, and the budget is what's left. It skips experiences that are already planned.
  - `plan(itinerary, state, seed, max_new=3)` is a greedy filler. It puts the best item into the earliest gap that yields one, and repeats. Intents already covered are dropped for the next pick so the plan mixes them. Locked stops never move.
  - `validate(itinerary, state, seed)` checks whole-sequence feasibility (doc §8.2): reachability including travel, opening hours and slots at the planned time, durations, the window cutoff, reaching the end point, and total budget. Completed stops aren't re-checked for reachability or hours.
- **`TravelerState.end_lat/end_lon`** (new) records "where you must be by `window_end`" (hotel, station, next booking). `feasibility.check` enforces it as a hard constraint, which also covers doc §13.2's "2 hours between lunch and my train".
- **`Stop.cost_inr`** (new) holds a stop's group cost, used for budget tracking.
- **`Recommendation`** now carries `lat`/`lon` (for the map in M6 and for itinerary stops).
- **`discover(..., skip=)`** lets the caller exclude experiences that are already in the itinerary.
- **`backend/tests/test_itinerary.py`** has 6 tests, all using an independent travel/sequence re-derivation:
  - The 90-min gap between a locked lunch and a locked City Palace booking returns only fills that validate.
  - `validate` catches unreachable and closed stops.
  - Scenario A produces a mixed, valid plan.
  - Locked stops never move.
  - The end-point constraint holds.
  - Relaxed pace adds slack.
- **`decisions.md`:** the hard constraints now include reaching the end point.

## Why
Doc §8: the traveler's existing itinerary is a first-class input. The real problem is filling the gaps around commitments feasibly, not generating a fresh list.

## Known gaps
- **Greedy planner:** with no stated intents it favours short, cheap stops (e.g. a 20-min lassi as the first morning stop), because score doesn't account for how much of the gap an item uses. Two fixes to consider: a time-use factor, or beam search (`ponytail:` note in `plan`). This is a good tuning task for the data/demo track, using the labelled personas.
- `max_new=3` leaves later gaps empty in long days. This is intentional, so the plan doesn't get overloaded.
- The "long transfer", "overloaded segment" and "weather-sensitive segment" states from doc §8.1 aren't flagged yet. Weather arrives with M4.
