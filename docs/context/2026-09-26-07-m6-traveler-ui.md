# 2026-09-26-07 · M6: traveler web app

## What changed
- `main` was fast-forwarded to M5 (`c2b6d0f`) at the team's request.
- **`frontend/`** is a Vite + React 19 + TypeScript app, hand-written with no template boilerplate. Its dependencies are react, react-dom and leaflet.
  - `src/api.ts` has types that mirror `docs/api.md` (only the fields the UI reads) plus a fetch helper. The helper surfaces the server's `detail` message on errors.
  - `src/MapView.tsx` uses plain Leaflet with OSM tiles. It shows pins for you, the recommendations and the plan, plus a dashed route. It uses `divIcon` pins, which avoids Leaflet's broken default-icon paths under bundlers.
  - `src/App.tsx` is the whole screen:
    - **Chat** with example prompts and a parser summary, e.g. "Understood (offline parser): 16:00–18:00, ₹1500, 4 people, 2 kids… 5 options fit; 31 ruled out."
    - **Situation chips**: window, spend/budget, group, mode, pace, weather, intents.
    - **"Something changed?" panel**: late 40 min, rain, next stop closed, tired, only ₹300 left. It shows a colour-coded diff with the reason and why.
    - **Recommendation cards** with engine reasons, a ⚠ low-confidence badge, and "Add to plan".
    - **Plan timeline** with lock/remove, "Fill free time", and validation problems or a ✓.
    - **"Why not the others?"** lists every exclusion reason.
    - A **demo clock** input that defaults to 2026-09-26 15:30. Every call uses it as "now", so demos are reproducible.
  - `src/styles.css` uses CSS tokens (terracotta accent) with dark mode via `prefers-color-scheme`, and collapses to one column below 900 px.
  - `vite.config.ts` proxies `/api` to `:8000`, so the backend doesn't need CORS.
- **Engine fixes found by driving the real UI:**
  - **`itinerary.insert()`** (new) and **`POST /plan {add}`**. "Add to plan" used to drop a recommendation in at its standalone time, which ignored the plan and caused overlaps. Now the engine fits it into the earliest feasible gap. If it fits nowhere, the API returns 409 "X doesn't fit around your current plan. Remove or unlock a stop to make room."
  - **`adapt._new_state`**: replanning now starts at max(now, **window_start**, end of the current stop) + delay. Before, a disruption triggered before the traveler's window (clock 15:30, window 16:00) scheduled replacements at 15:45.
  - Tests were added for both: `test_insert_fits_a_chosen_experience_into_a_feasible_gap`, `test_plan_add_fits_or_explains`, and `test_event_before_the_window_never_plans_before_it`.
- **CI:** a `frontend` job runs `npm ci` and `npm run build`, which includes `tsc --noEmit`.
- **Docs:** `docs/api.md` (the `add` parameter and the edit flow), README "Run it" (both servers), `CLAUDE.md` commands, and roadmap M6 ✅.
- **`.claude/launch.json`** is local-only and gitignored. It holds Windows paths for the Claude preview tools.

## Why
M6 is doc §11: the interaction layer consumes the engine's decisions. The map shows engine output rather than a database of pins, and explanations come straight from the engine's reasons.

## Known gaps
- Replaced and dropped stops stay in the timeline struck through, which is good for the demo diff but piles up across many events. Hide them if it gets noisy.
- Recommendation cards hide the first 3 reasons (distance, time, cost), because the meta line already shows them.
- There's no frontend unit test. `tsc` + build in CI, plus the browser pass above, cover it for a hackathon.
- The OSM tile policy is fine for demos. For heavier use, switch to a tile provider with a key.
- The demo clock is manual. For the live demo, set it deliberately before each disruption (see the demo steps below).

## Demo steps (5 min)
1. Keep the clock at 15:30 and click Send on the family example. Point out the reasons, the ⚠ badge, "why not Hawa Mahal", and the map.
2. Click "Add to plan" on Masala Chowk to show the honest "doesn't fit" message. Lock the puppet show.
3. "Next stop closed", then "Only ₹300 left": show the diff with reasons, the struck-through old stops, and the ✓ check.
4. Type "actually, something less crowded". Refinement keeps the rest of the context and the locked stop.
