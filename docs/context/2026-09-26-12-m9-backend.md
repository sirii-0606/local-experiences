# 2026-09-26-12 · Backend check + remaining M9 backend (ratings, ownership, bookings)

## What changed
The user said "check the backend, I guess it is not working" and "build the backend that is left". This branch is `feat/m9-backend`, stacked on `feat/ui-polish`.

- **Backend check (it was working).**
  - The user's terminal showed every call (`/chat`, `/plan`, `/weather`, `/catalog`, `/providers/insights`) returning 200 until Ctrl+C, which stops both servers.
  - A fresh server answered all 14 endpoints, and 78 tests passed.
  - The one confusing thing was `http://localhost:8000/` returning `{"detail":"Not Found"}`, because the API had no home page. **Fixed:** `/` now redirects to `/docs`.
  - Separately, the user's `cd local-experiences` failed only because they were already inside the repo.
- **Post-visit ratings → confidence** (`engine/confidence.py::with_ratings`, `store.py` `ratings` table, `/feedback` with `kind: "rating"`):
  - Stars and "as described?" are folded into the rating and review count.
  - When most visits confirm the listing, the latest visit becomes `traveler` evidence for hours and price. It replaces provider claims and older traveler evidence, but never `verified`. The low-confidence badge clears honestly.
  - Disputes block the upgrade.
- **Provider ownership + edits:**
  - `POST /providers/listings` returns an `edit_token`, stored as a sha256 hash in a new `owners` table and compared in constant time.
  - New endpoints: `GET /providers/listings/{id}` (as an editable draft, via `provider.to_draft`), `PUT` (edits in place, same ids, via `to_listing(key=…)`), and `DELETE`.
  - `/providers/availability` now needs the `X-Provider-Token` header for provider listings (403 otherwise). Seed experiences stay open in the demo unless `SEED_ADMIN_TOKEN` is set.
- **Booking stub** (`POST /bookings`, `DELETE /bookings/{code}`, `bookings` table):
  - It holds spots for a planned stop against capacity at that start time, returns a code like `LE-F5BDBE`, and marks the stop confirmed and locked.
  - It returns 409 with a reason when the stop doesn't validate or the slot is full ("only 0 spots left at 16:15 for 4 of you").
  - Provider insights now include `booked_people`, `rating` and `review_count`.
- **Schema safety:** the new tables are separate `create table if not exists` statements, so existing demo DBs keep working without a migration.
- **Frontend:**
  - `api.ts` keeps provider edit tokens in localStorage and sends the header automatically. New calls: `book`, `rate`, `listing`, `updateListing` and `deleteListing`.
  - Plan stops show **🎟 Book** for upcoming proposed stops, and a **"How was it?"** star rating once a stop's end time is past the demo clock. A note shows the booking code or thanks for the rating.
  - The Provider tab shows **Edit listing** (which reuses the draft form, saved as "Save changes") and **Remove listing** for your own listings. Listings owned in another browser explain why they can't be changed. Insights show booked, ★ rating and review count.
- **Docs:** `docs/api.md` (7 new rows), `decisions.md` (2 rows), and the roadmap M9 line.

## Why
These were the roadmap's remaining backend items: ratings (M9.2), provider accounts/edits, and the booking stub. They close the "anyone can pause anyone's listing" gap from M7 and give doc §6.3 its independent-evidence loop.
