# 2026-09-26-03 · M2: feasibility + ranking engine

## What changed
- **`backend/app/engine/feasibility.py`** checks the hard constraints. It never scores.
  - `km_between` (haversine) and `travel_min` (× 1.3 road factor ÷ mode speed + 10 min buffer).
  - `group_cost` and `earliest_start` (respects fixed slots and one-off `on_date` events).
  - `check(exp, state, seed) -> Fit` returns start/end, km, travel time, cost, and **human-readable reasons when infeasible**. Examples: "no time left to fit its 45 min after you arrive at 16:00 (open 09:00–16:30)", "costs ₹4800 for 4, over your ₹1500 budget", "not running on Monday 28 Sep".
  - It checks the time window (travel included), opening hours and slots, budget, capacity, minimum age, required accessibility (which must also be confirmed, with confidence ≥ 0.5), indoor-only, and max distance.
- **`backend/app/engine/confidence.py`** provides `attr_confidence`, which scores each attribute from evidence source and recency, falling back to verification status and review volume.
- **`backend/app/engine/rank.py`** provides `discover(state, seed, k=5) -> (recommendations, excluded)`.
  - Scoring is the weighted utility from `decisions.md` plus a novelty term, followed by an MMR diversity pass (λ = 0.8).
  - Each `Recommendation` carries `factors` (the numbers behind the score) and `reasons` (built from those same factors, per doc §7.5), with ⚠ lines for stale or unconfirmed info.
  - `excluded` maps every rejected experience to its reasons, which is the answer to "why not the museum?".
- **`backend/tests/test_engine.py`** has 14 tests:
  - 8 personas, each checked by an **independent feasibility validator** that re-derives distance, hours, slots, cost, capacity, age and accessibility without engine code.
  - Behaviour tests: scenario A, low confidence is flagged but not hidden, one-off event dates, unconfirmed accessibility fails, "iconic" intent rewards popularity, and a hidden-gems persona gets low-tourist places.
- **Ruff:** `pyproject.toml` now pins lint rules (`E, F, I, B, UP`). Ruff 0.16 enabled a wide default set that would drift between machines and CI.
- **`decisions.md`:**
  - The confidence formula is now the implemented one (90-day decay toward half weight; the 30-day half-life flagged almost everything).
  - MMR λ goes from 0.7 to 0.8, because 0.7 put intent-less items above intent matches.
  - Factor definitions are written out.

## Why
This is the core of the product (doc §7): check feasibility before ranking, keep hard constraints separate from soft preferences, and generate explanations from the same factors used for the decision.

## Known gaps
- There's no weather or closure context yet. Rain and closures arrive with `ContextEvent` in M4, and will become an extra hard or context input to `check`/`_factors`.
- There's no return trip in discover mode: an item only has to *end* by the cutoff. Travel to the next fixed stop is M3's job, via itinerary gaps.
- Feedback-based learning (accepted/rejected items shifting scores) is M8.
- A window is a single day; spans past midnight aren't supported. Times are naive local IST.
- The review-count fallback in confidence applies to accessibility too (marked `ponytail:`).
